# Internal documentation map

Read [AGENTS.md](../AGENTS.md) and [PROJECT_STATE.md](PROJECT_STATE.md) before substantive repository work. Then load only the route that matches the task.

| Question | Authoritative route |
| --- | --- |
| What is current? | [PROJECT_STATE.md](PROJECT_STATE.md) |
| What product and architecture decisions are implemented? | [DECISIONS.md](DECISIONS.md), then the linked source and tests |
| How should repository work be prepared and validated? | [DEVELOPMENT.md](DEVELOPMENT.md) |
| What is the live release policy and where is release evidence? | [RELEASES.md](RELEASES.md) |
| What is the current provenance and notice decision? | [PROVENANCE_AUDIT.md](../PROVENANCE_AUDIT.md) |
| How does a user install or operate the package? | [Package documentation index](../com.torproduction.addressables/Documentation~/com.torproduction.addressables.md) |
| Why and how was the original implementation completed? | Archived [ImplementationPlan.md](../ImplementationPlan.md), on demand only |
| Why is the documentation organized this way? | [CONTEXT_ARCHITECTURE.md](CONTEXT_ARCHITECTURE.md) |

Source, tests, package manifests, workflows, Git refs, and committed release artifacts are stronger evidence than summaries. If a current document conflicts with those sources, correct the document rather than treating the summary as an override.
